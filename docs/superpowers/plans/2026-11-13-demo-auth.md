# Demo JWT authentication implementation plan

Goal: two seeded demo accounts authenticate using HttpOnly JWT cookies and use different existing BTC customer profiles in text and voice.

Architecture: backend owns runtime.demo_users (unique username and customer_id, Argon2 password hash). JWT subject identifies the account; each request resolves current profile from PostgreSQL. No changes to BTC source tables. Browser cannot override assigned identity. JWT expiry closes WebSockets. Same-origin checks protect cookie-authenticated writes and WebSocket handshakes.

Constraints: current checkout, no subagents, no live model calls; focused offline tests only. Implementation is authorized by the user's request to execute the agreed design. No refresh tokens, registration, account administration or memory schema changes. Knowledge permissions remain server-managed; require demo login at gateway.

1. Add failing API and WebSocket tests: missing/invalid/expired JWT, bad password, cookie flags, logout, cross-origin rejection, two concurrent accounts with forged channel identity.
2. Add PostgreSQL migration, repository, seed CLI with two configured profiles and non-overwriting inserts; verify real database constraints and idempotence offline where available.
3. Add auth routes/dependencies, gateway lifecycle and socket expiry/profile binding; run new tests and existing focused text/voice/knowledge tests with explicit test-only authentication fixtures.
4. Add login/logout UI and server profile selection, update env and run instructions; verify with offline browser integration.
5. Review diff and run focused verification for changed behavior. Report setup and limitations.
