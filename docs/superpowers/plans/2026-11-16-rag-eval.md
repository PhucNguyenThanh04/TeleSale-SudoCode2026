# Independent RAG Eval Implementation Plan

> Execute inline using superpowers:executing-plans; repository instructions override worktree, delegation, full-suite and approval workflows.

**Goal:** Deliver an independent, replayable RAG evaluator ready for the user to run live.
**Architecture:** Frozen BTC inputs → MCP retrieval → optional isolated generation → offline BTC/code scoring → optional saved-output Ragas/business judging.
**Tech Stack:** Python, existing MCP/LLM clients, BTC scorer, optional Ragas 0.4.4.
**Spec:** `docs/superpowers/specs/2026-11-16-rag-eval-design.md`

## Constraints

Current checkout only; preserve unrelated edits. No subagents, paid calls, database
resets or production modifications. Exact QA coverage; no labels in generation.
No automatic judge/generation calls during replay. No overwrite of runs.

## Review focus

1. Incomplete/duplicate trace must not inflate BTC recall.
2. Reported dates must not become verified facts silently.
3. Raw internal fields from BTC tools must not reach generator or logs.
4. Linked evidence must retain actual ordering and budget semantics.
5. Judge/model failures and artifact edits must remain visible.
